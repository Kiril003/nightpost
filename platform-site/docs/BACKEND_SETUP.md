# Що зробити у Supabase, Cloudflare R2 і пошті

Це не загальні поради, а точний перелік під наш код. Усе, що тут написано,
робиться **один раз**. Після цього кабінет, акаунти, ролі, листування й
завантаження збірок працюють на живому домені.

## Рішення, які вже прийнято (щоб не переробляти)

**Supabase беремо лише як базу даних.** Postgres із бекапами, точкою
відновлення й вебпанеллю. **Supabase Auth НЕ вмикаємо.** Причина конкретна: у
нас уже є своя особа — пошта, підтверджена одноразовим кодом, і власні сесії
(`server/accounts.py`). Два механізми входу в одному продукті — це рівно та
плутанина, через яку `phantom-website` має свій `/login`, несумісний із
кабінетом. Один вхід, одна таблиця `accounts`, одна роль.

**Ключ ліцензії лишається перепусткою застосунку, а не паролем кабінету.**
Ключ можна загубити — і саме тоді кабінет потрібен найбільше.

**R2 — сховище збірок, закрите.** Файли не роздаються публічним посиланням.
Сервер підписує адресу на 5 хвилин і лише тому, у кого чинна ліцензія
(`server/storage.py`).

## 1. Supabase

1. **supabase.com → New project.**
   - Name: `phantom`
   - Database password: згенеруй довгий, збережи в менеджері паролів — його
     більше ніде не покажуть.
   - Region: `eu-central-1` (Франкфурт) — найближчий до України з наявних.
2. **Таблиці створювати руками не треба.** Сервер сам будує схему, дописує
   пізніші колонки й вмикає RLS на першому запуску з `DATABASE_URL`. Файл
   `server/supabase/schema.sql` лишається довідкою: подивитись, що зʼявиться
   в базі. Виконати його в SQL Editor теж можна — сервер стартує поверх уже
   створених таблиць, це перевірено.
3. **Table Editor** — після першого запуску сервера має бути десять таблиць:
   `accounts`, `sessions`, `login_codes`, `licenses`, `activations`, `threads`,
   `messages`, `recoveries`, `waitlist`, `events`.
4. **Connect** (кнопка вгорі проєкту) → блок **Session pooler** → скопіювати
   URI виду
   `postgresql://postgres.xxxx:ПАРОЛЬ@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`.
   Це значення поїде в `DATABASE_URL`.
   **Чому пулер, а не Direct connection:** пряма адреса `db.xxxx.supabase.co`
   у нових проєктах відповідає лише по IPv6, і хостинг без IPv6 просто не
   достукається. Пулер працює по IPv4. Транзакційний пулер (порт `6543`) теж
   годиться — сервер уже налаштований не тримати підготовлених виразів.
5. **Project Settings → API.** Скопіювати `service_role` ключ (він секретний,
   у браузер ніколи не потрапляє). Знадобиться, якщо колись підемо через
   REST замість прямого підключення.

**Чого НЕ робити:** не вмикати Authentication → Providers, не створювати
політики RLS «для зручності». Схема навмисно закрита для anon-ключа: RLS
увімкнено на всіх десяти таблицях, політик — жодної, і навіть роль із явним
`GRANT SELECT` бачить нуль рядків (перевірено на живому Postgres).

## 2. Cloudflare R2

1. **dash.cloudflare.com → R2 → Create bucket.**
   - Name: `phantom-builds`
   - Location: Automatic
   - **Public access: вимкнено** (лишити як є). Бакет має бути закритим.
2. **R2 → Manage API tokens → Create API token.**
   - Permissions: **Object Read & Write**
   - Specify bucket: `phantom-builds`
   - TTL: без обмеження
   - Після створення показують **Access Key ID** і **Secret Access Key** —
     секрет видно **один раз**, збережи одразу.
3. Там же видно **Account ID** (або в адресі S3-ендпоїнта
   `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`).
4. Коли з'являться справжні збірки — покласти їх у бакет теками:
   `builds/phantom-companion-1.0.apk`, `builds/phantom-os-1.0.AppImage` тощо.

Домен для R2 **не потрібен**: посилання підписується на S3-ендпоїнт напряму.

## 3. Пошта

Без неї не працює ні вхід, ні відновлення ключа — код просто нікуди не піде.
Підійде будь-який SMTP; найпростіші варіанти:

- **Resend** (resend.com) — доменну пошту підтверджують DNS-записами в
  Cloudflare, безкоштовно 3000 листів/міс. SMTP: `smtp.resend.com`, порт `587`,
  користувач `resend`, пароль — API-ключ.
- **Fastmail / власна скринька** — теж годиться, головне SMTP із паролем
  застосунку.

Що б не обрав, у DNS Cloudflare для `phantom-os.dev` треба буде додати записи
SPF/DKIM, які покаже сервіс, — інакше листи підуть у спам.

## 4. Де живе сервер

Сервер ліцензій — це Python-застосунок (`platform-site/server`). Netlify його
не хостить: там лише статичний сайт. Найдешевші робочі варіанти:

- **Fly.io** — безкоштовна машина 256 МБ вистачає з запасом;
- **Railway / Render** — простіше, але платно з першого дня;
- **будь-який VPS** за 4–5 $ із `systemd` + Caddy.

Домен: **`license.phantom-os.dev`** — у Cloudflare додати `CNAME` (або `A`) на
адресу, яку дасть хостинг. Саме ця адреса вже стоїть у коді сайту
(`src/lib/meta.ts:11`), тож міняти нічого не доведеться.

## 5. Що вписати в `.env`

Файл `platform-site/server/.env` (права 600, під `.gitignore`) — **не в чат**:
все, що пройшло через переписку, доводиться потім перевипускати.

```
DATABASE_URL=postgresql://postgres.xxxx:...@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
OWNER_EMAIL=myloserdovkiril@gmail.com

SMTP_HOST=smtp.resend.com
SMTP_PORT=587
SMTP_USER=resend
SMTP_PASSWORD=...
SMTP_FROM=no-reply@phantom-os.dev

R2_ACCOUNT_ID=...
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_BUCKET=phantom-builds
R2_BUILDS=android:builds/phantom-companion-1.0.apk,linux:builds/phantom-os-1.0.AppImage

ADMIN_TOKEN=<довгий випадковий рядок>
SITE_ORIGINS=https://phantom-os.dev,https://www.phantom-os.dev
LS_WEBHOOK_SECRET=<із кабінету LemonSqueezy>
```

`OWNER_EMAIL` — критичний рядок: акаунт із цією поштою отримує роль `owner`
при першому ж вході, і лише власник роздає ролі решті. Без нього перша роль не
береться нізвідки.

`DOWNLOAD_POLICY` — кому видається збірка з кабінету. `licence` (типово) —
лише власникам чинного ключа; `account` — кожному, хто ввійшов у кабінет.
Це і є вимикач «доступний кожному», одна команда без перевикладання коду:

```
fly secrets set --app phantom-license DOWNLOAD_POLICY=account
```

## 6. Як перевірити, що все живе

```bash
curl https://license.phantom-os.dev/healthz          # {"ok":true,...}
```

Далі на сайті `/account`: ввести свою пошту → лист із кодом має прийти за
секунди → після входу під заголовком з'явиться чорна плашка **OWNER**, а в лівій
смузі — розділи «Зведення», «Звернення», «Люди», «Усі ліцензії», «Журнал».
Якщо плашки немає — `OWNER_EMAIL` не збігся з введеною поштою.

## 7. Чого ще немає

- **Передача ліцензії іншій людині** — ручки немає; спершу треба вирішити, що
  саме це означає: назавжди віддати ключ чи лише звільнити місце пристрою.
- **Оплата** — вебхук LemonSqueezy написаний і працює, але виплати вимагають
  юрособи (ФОП вони можуть не взяти — звірити перед підключенням).
- **Збірки** — поки їх немає, `/account → Завантаження` чесно каже «Збірок ще
  не опубліковано», замість того щоб показувати мертві кнопки.
