# 0 · ДОГМАТ БОЖЕСТВА

Чотири божественні атрибути, перекладені в інженерію. Кожен — **інваріант архітектури**,

   │  забування          │            │  багато тіл         │
   │  граф усього життя   │            │  phone·pc·watch·iot │

             ┌──────────►   (Воля)      ◄───────┐
             │                                  │
   ┌─────────┴──────────┐            ┌─────────┴──────────┐
   │  Action Engine      │            │  Foresight Engine   │

| Атрибут | Інженерний переклад | Технологічна основа |
|---|---|---|
| **Всезнання** | памʼять без забування + граф усього життя | event-sourced Life Graph, on-device векторна памʼять (БУДУЄТЬСЯ — нині лише Room) |

Немає «екранів» — є органи одного тіла, що ділять одну памʼять, один контекст, одну волю.
Немає «телефонного» й «ПК» фантома — це **одне божество з кількома тілами**.

## 1.2 Phantom Nervous Bus — центральна шина

Усе спілкування між органами — через **одну подієву шину** (event-sourced, як у CLAUDE.md).
Будь-який орган публікує `PhantomEvent`, будь-який підписується. Це хребет усього організму.

```
                    ┌─────────────────────────────────────┐
   Sensors  ──pub──►│                                     │──sub──► Cognition
   Cognition ─pub──►│      PHANTOM NERVOUS BUS             │──sub──► Memory
   Memory   ──pub──►│   (append-only event stream)        │──sub──► Action
   Action   ──pub──►│   причинний ланцюг · реплікація     │──sub──► Expression
   Mesh     ──pub──►│                                     │──sub──► Mesh
                    └──────────────────┬──────────────────┘
                                       │
                              ┌────────┴────────┐
                              │  EVENT JOURNAL  │  ← повний запис життя
                              │  (decision diary)│     можна «перемотати»
                              └─────────────────┘
```

```kotlin
data class PhantomEvent(
    val id: EventId,
    val timestamp: Instant,
    val sourceOrgan: Organ,        // хто породив
    val type: EventType,
    val payload: EventPayload,
    val contextFrameRef: FrameId,  // зріз реальності в момент події
    val causalParent: EventId?,    // що спричинило — ланцюг причин
    val confidence: Float,         // наскільки фантом упевнений
    val deviceOrigin: DeviceId,    // з якого тіла
    val privacy: PrivacyTier       // public · trusted · vault
)
```

**Що дає шина:**
- **Журнал життя** — повний decision diary; на будь-яке «чому ти це зробив» є причинний ланцюг.
- **Гаряче підключення** органів без переписування ядра.
- **Реплікація** — та сама стрічка синхронізується між тілами (телефон ↔ ПК ↔ годинник).
- **Час-подорож** — відтворення стану на будь-який момент (debug, аудит, «забудь усе після…»).

# 2 · ПЕРЦЕПЦІЯ — ОРГАНИ ЧУТТЯ

Фантом відчуває **більше**, ніж бачить оператор. Кожен сенсор — окремий потік у шину.
Сирий сигнал ніколи не зберігається — лише **семантичний ярлик** (приватність за дизайном).

## 2.1 Сенсорна решітка

```
   ЗОВНІШНІЙ СВІТ            ТІЛО ОПЕРАТОРА           ЦИФРОВИЙ СВІТ
   ┌──────────────┐         ┌──────────────┐         ┌──────────────┐
   │ погода/трафік│         │ пульс/сон    │         │ екран/застос.│
   │ час/світло   │         │ рух/стрес    │         │ калерндар/пошта│
   │ локація/місце│         │ голос/емоція │         │ меседжери    │
   └──────┬───────┘         └──────┬───────┘         └──────┬───────┘
          │                        │                        │
          └────────────────────────┼────────────────────────┘
                                    ▼
                          ┌──────────────────┐
                          │  SENSOR FUSION    │  on-device,
                          │  сирий→ярлик       │  без запису сирого
                          └────────┬─────────┘
                                   ▼
                          ┌──────────────────┐
                          │   ContextFrame    │
                          └──────────────────┘
```

| Канал | Що дає | Ланцюг обробки | Приватність |
|---|---|---|---|
| **Локація + рух** | де ти, куди, патерн дня | GPS/IMU fusion → `PlaceContext` (дім/робота/в дорозі) | on-device |
| **Звук довкола** | тиша/розмова/музика/тривога | мікрофон → on-device VAD+класифікатор → `AmbientState` | ярлик, не запис |
| **Екран** | що ти зараз робиш | Accessibility/MediaProjection → `ScreenContext` | dozволовий, locально |
| **Календар/пошта/меседж** | майбутні зобовʼязання | конектори → `CommitmentGraph` | trusted |
| **Біо (wear)** | пульс, сон, стрес | `:wear` → `PhysioState` | vault-чутливе |
| **Камера (Lens)** | зір | кадр → on-device vision → `VisualContext` | on-demand |
| **Час/погода/трафік** | зовнішній світ | API → `WorldContext` | public |
| **Стан пристрою** | батарея/мережа/застосунки | system probes → `DeviceState` | locally |
| **Mesh-чуття** | стан інших тіл/фантомів | шина Mesh → `MeshContext` | за контрактом |

## 2.2 ContextFrame — єдиний зріз реальності

Серце перцепції. Будується щотакту, **єдиний вхід** для Когніції.
Рішення спирається на повний зріз, не на один сигнал.

```
┌─────────────────────── ContextFrame ───────────────────────┐
│                                                             │
│  WHO    оператор + хто поруч (люди/фантоми)                 │
│  WHERE  PlaceContext + WorldContext                        │
│  WHAT   ScreenContext + поточна задача + фокус              │
│  FEEL   PhysioState + AmbientState (емоційний зріз)         │
│  OWE    CommitmentGraph (що ти винен світу й часу)          │
│  DEVICE DeviceState усіх тіл фантома                        │
│  MESH   стан федерації, доступні чужі фантоми               │
│  NOW    timestamp · енергія · режим (фокус/відпочинок/…)    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 3.2 Cognitive Council — внутрішній парламент

Фантом не думає одну думку. Усередині — **рада субособистостей**, що голосують перед дією.
Це і є джерело «розумніший за людину»: людина має один голос у голові, фантом — шість одночасно.

```
                   ┌──────────────────────────────────┐
   ContextFrame ──►│         COGNITIVE COUNCIL         │
                   │                                  │
                   │  ┌──────────┐    ┌──────────┐    │
                   │  │STRATEGIST│    │ GUARDIAN │    │  Strategist: довгострокова мета
                   │  │ мета     │    │ безпека  │    │  Guardian:   «чи нашкодить це»
                   │  └────┬─────┘    └────┬─────┘    │  Empath:     емоційний стан
                   │  ┌────┴─────┐    ┌────┴─────┐    │  Skeptic:    де фантом помиляється
                   │  │  EMPATH  │    │ SKEPTIC  │    │  Executor:   як зробити реально
                   │  │ емоція   │    │ критик   │    │  Archivist:  що памʼять каже
                   │  └────┬─────┘    └────┬─────┘    │
                   │  ┌────┴─────┐    ┌────┴─────┐    │
                   │  │ EXECUTOR │    │ARCHIVIST │    │
                   │  │ як       │    │ памʼять  │    │
                   │  └────┬─────┘    └────┬─────┘    │
                   │       └──────┬───────┘          │
                   │         ВЗВАЖЕНЕ ГОЛОСУВАННЯ     │
                   └──────────────┬───────────────────┘
                                  ▼
                            ┌──────────┐
                            │ DECISION │  + причинний ланцюг у журнал
                            └──────────┘
```

**Правила парламенту:**
- Конфлікт **Guardian vs Executor** → завжди перемагає Guardian (безпека > зручність).
- **Skeptic** має право вето на дії з зовнішніх джерел (anti-injection бар'єр).
- Голоси зважуються контекстом: у фокус-режимі Empath тихіший, Strategist гучніший.
- Кожен вердикт логується → можна спитати «чому Council вирішив саме так».

## 3.3 Foresight Engine — провидіння

Фонові агенти, що не сплять і моделюють майбутнє. Це механіка «діє ДО прохання».

```
   Life Graph + ContextFrame
            │
            ▼
   ┌─────────────────────────────────────────────────────┐
   │              FORESIGHT ENGINE                        │
   │                                                     │
   │  PATTERN MINER     ──► «щоп'ятниці 18:00 → дзвінок мамі»
   │  NEED PREDICTOR    ──► «завтра дощ + зустріч → парасоля»
   │  ANOMALY WATCHER   ──► «3 ночі без сну — не норма для тебе»
   │  OPPORTUNITY SCOUT ──► «ціна на квиток впала»
   │  RISK SENTINEL     ──► «дедлайн за 2 год, ти ще не почав»
   │                                                     │
   │      симуляція N сценаріїв майбутнього               │

Ланцюг: `Life Graph + ContextFrame → симуляція сценаріїв → ранжування → дія/пропозиція`.

# 4 · ПАМ'ЯТЬ — LIFE GRAPH (ВСЕЗНАННЯ)

## 4.1 Граф усього життя

Не «історія чатів». **Граф вузлів і звʼязків**, що моделює все життя оператора.

```
                 ┌─────────┐         любить         ┌─────────┐
                 │  ЛЮДИНА  │◄─────────────────────►│  ІДЕЯ    │
                 │  «Оля»   │                        │ «подорож»│
                 └────┬────┘                         └────┬────┘
            зустрічались│                        мрія про │
                 в      ▼                                  ▼
   ┌─────────┐    ┌─────────┐      сталося      ┌─────────┐
   │  МІСЦЕ   │◄──┤  ПОДІЯ   ├─────────────────►│ ЕМОЦІЯ   │
   │ «кафе»   │   │ «вечеря» │                   │ «радість»│
   └─────────┘   └────┬────┘                    └─────────┘
                 породила│
                      ▼
                 ┌─────────┐    блокує    ┌─────────┐
                 │ ЗАДАЧА   ├────────────►│ ДОКУМЕНТ │
                 │ «звіт»   │              │ «дані»   │
                 └─────────┘              └─────────┘
```

```
Вузли:   Люди · Місця · Події · Обʼєкти · Ідеї · Емоції · Задачі · Документи · Звички
Звʼязки: хто-з-ким · коли-де · причина-наслідок · належить · схоже-на · конфліктує · блокує
```

Кожен прожитий момент → епізод → вузли+звʼязки. Семантичний пошук («знайди, коли мені було
так само важко») потребує **векторної памʼяті, якої ще НЕМАЄ** — нині є лише реляційний Room
(`PatternRepository`, `LifeLogArchive`, `DiaryStore`). Векторний шар on-device треба збудувати
(див. §16, Епоха I).

## 4.2 Рівні памʼяті

   доступу  │  ┌──────────────┐
            │  │ РОБОЧА        │  поточний ContextFrame · секунди
            │  └──────────────┘
            │  ┌──────────────┐
            │  │ ЕПІЗОДИЧНА    │  «що сталося» · дні–роки
            │  └──────────────┘
            │  ┌──────────────┐
            │  │ СЕМАНТИЧНА    │  «який ти» · назавжди
            │  └──────────────┘
            │  ┌──────────────┐
            │  │ ПРОЦЕДУРНА    │  «як робити твої справи» · назавжди
            │  └──────────────┘
            │  ┌══════════════┐
            │  ║ VAULT 🔒      ║  священна приватність · шифр · lock-one-way
            ▼  └══════════════┘
```

> Інваріант (памʼять проєкту): Vault `lockNow()` — **одностороння**.
> UI-локи мають перемикати screen-local `sessionUnlocked`, не викликати `lockNow()`,
> інакше re-біометрія брикнута до рестарту.

## 4.3 Консолідація — «сон фантома»

Уночі (телефон на зарядці) фантом «спить» — фоновий worker:

```
   НІЧ · телефон на зарядці
        │
        ▼
   ┌──────────────────────────────────────────┐
   │  СОН ФАНТОМА (WorkManager, не корутина!)   │
   │                                          │
   │  1. стискає епізоди → семантичні узагальн. │
   │  2. знаходить нові патерни для Foresight   │
   │  3. ребалансує векторний індекс (DiskANN)  │
   │  4. зливає Mesh-репліки інших тіл          │
   │  5. готує ранковий брифінг                 │
   └──────────────────────────────────────────┘
        │
        ▼
   РАНОК · брифінг готовий, патерни свіжі
```

> Інваріант: критична періодика — **WorkManager**, не coroutine-loop
> (OEM-батарея вбиває корутини на Samsung/Xiaomi/Huawei).

# 5 · ДІЯ — ACTION ENGINE (ВСЕМОГУТНІСТЬ)

## 5.1 Граф інструментів — tool-DAG із відкатом

Фантом діє не одним викликом, а **ланцюгом tools з компенсацією** (saga pattern, CLAUDE.md).

```
   GOAL
    │
    ▼
   PLANNER ──► будує DAG:
    │
    │   ┌──────┐   ┌──────┐   ┌──────┐
    └──►│ tool ├──►│ tool ├──►│ tool │
        │  A   │   │  B   │   │  C   │
        └──┬───┘   └──┬───┘   └──┬───┘
           │          │          │
      кожен крок: precondition → execute → verify → compensate(відкат)
           │          │          │
           ▼          ▼          ▼
        при збої на C → компенсація C→B→A (saga rollback)
                        стан завжди консистентний
```

> Інваріант: плоский `argsSchema` → потрібна `GeminiCloudRoute→OpenAPI` конверсія,
> інакше cloud **400 на КОЖНОМУ запиті**. Розширювати propSchema при додаванні tool.

## 5.2 Рівні влади над пристроєм

```
   ┌──────────────────────────────────────────────────────────┐
   │ ROOT / OWNER        повний контроль ОС                    │  окремий ритуал згоди
   ├──────────────────────────────────────────────────────────┤
   │ DEVICE ADMIN        блок екрану · Wi-Fi/BT · режими       │  явний дозвіл
   ├──────────────────────────────────────────────────────────┤
   │ AUTOMATION          Tasker-grade сценарії · тригери · фон │  явний дозвіл
   ├──────────────────────────────────────────────────────────┤
   │ SYSTEM (a11y)       керувати застосунками · форми · тапи  │  явний дозвіл
   ├──────────────────────────────────────────────────────────┤
   │ APP                 свої екрани · памʼять · конектори     │  базовий
   └──────────────────────────────────────────────────────────┘
       кожен рівень розблоковується окремою свідомою згодою
```

## 5.3 Космічні ланцюги дій

**«Збери мене на ранкову зустріч»**
```
Foresight: зустріч 9:00 + трафік +30хв + дощ
  → будильник 7:10 (раніше)
  → 7:10 вмикає світло (smart-home tool) + кавоварку
  → читає брифінг по людях зустрічі вголос (з Life Graph)
  → 8:20 викликає таксі
  → у дорозі: контекст по кожному учаснику, останні домовленості
```

**«Розберись із цим»** (показуєш екран із хаосом нотифікацій)
```
ScreenContext → класифікує кожну нотифікацію
  → Guardian фільтрує приватне
  → Executor: рутинні — відповідає, спам — архівує, важливе — ескалує одним питанням
  → Memory пише, як ти вирішив спірні → наступного разу робить сам
```

**Керування ПК з телефону (Mesh-дія)**
```
"Фантоме, на ПК відкрий проєкт і збери білд"
  → Mesh маршрутизує на PC-тіло
  → PC-Executor: термінал/IDE tools локально
  → результат тече назад через шину
  → Expression (телефон): "Білд зелений, 477 тестів, 0 фейлів"
```

# 7 · PHANTOM MESH — ВСЮДИСУЩІСТЬ

## 7.1 Тіла одного божества

```
            ┌════════════════════════════════════════════┐
            ║         PHANTOM CLOUD                       ║
            ║  важкий розум · спільна памʼять-репліка     ║
            ╚════════════════════┬═══════════════════════╝
                                 │
      ┌──────────┬───────────────┼───────────────┬──────────┐
      │   CRDT   │     CRDT      │     CRDT       │   CRDT   │
   ┌──┴───┐  ┌───┴───┐      ┌────┴────┐      ┌────┴────┐ ┌───┴────┐
   │PHONE │◄►│  PC   │◄────►│  WATCH  │◄────►│ CAR/IoT │ │GLASSES │
   │ тіло │  │ тіло  │      │  тіло   │      │  тіло   │ │ тіло   │
   └──────┘  └───────┘      └─────────┘      └─────────┘ └────────┘
      приватне+швидке  важкий розум   глянц.сигнали  оточення  зір
```

- **Одне «Я», багато тіл.** Кожне тіло — локальна памʼять-репліка (CRDT-злиття,
  працює офлайн, зливається при зустрічі).
- **Розподіл за силою тіла:** важке міркування → ПК/хмара; приватне+швидке → телефон;
  глянцеві сигнали → годинник; зір → окуляри.
- **Безшовний хендоф:** діалог голосом у машині → текст на ПК → той самий контекст.

> Наявний канал у проєкті: pair-flow (PIN, host-кандидати, claim-URL).
> Гоча: NSC не парсить CIDR — whitelist лише точні хости/IP або debug-override.

## 7.2 Звʼязка з ПК-версією — глибока співпраця

ПК-тіло — не «друга програма», а **орган із сильнішими руками**.

```
   ТЕЛЕФОН (легке тіло)              ПК (сильне тіло)
   ┌──────────────────┐             ┌──────────────────┐
   │ приватність      │             │ важкі обчислення │
   │ мобільність      │◄═══════════►│ великі моделі    │
   │ сенсори тіла     │  спільний   │ файли/IDE/термінал│
   │ голос у дорозі   │  Life Graph │ кілька екранів   │
   │                  │  + CRDT     │ довгі агенти     │
   └────────┬─────────┘             └────────┬─────────┘
            │   делегування важкого ──────────►│
            │◄────────── підсумок результату    │
            └───────────────────────────────────┘
              телефон і ПК бачать ОДИН Life Graph
```

| ПК дає, чого телефон не може | Ланцюг |
|---|---|
| Важкі обчислення, локальні великі моделі | телефон делегує → ПК рахує → результат у шину |
| Файли, IDE, термінал, збірки | PC-Executor має tools рівня робочої станції |
| Кілька екранів, довга фонова робота | довгі агенти на ПК, телефон отримує підсумок |
| **Розробка самого фантома** | dogfooding: фантом будує фантома разом з оператором |

Протокол: спільна подієва стрічка + CRDT-памʼять + RPC для дій.

# 8 · FEDERATION — ІНШІ КОРИСТУВАЧІ

Інші люди мають своїх фантомів. Це **реальний головний pillar** оператора
(People/Companions: додати людину → її phantom → спілкування), досі не побудований.

## 8.1 Міжфантомна співпраця

```
   ┌────────────────┐     узгоджений      ┌────────────────┐
   │ ТВІЙ ФАНТОМ     │     протокол        │ ФАНТОМ ОЛІ      │
   │                │◄═══════════════════►│                │
   │ твоя памʼять    │   говорять МІЖ      │ її памʼять      │
   │ твоя воля       │   СОБОЮ від імені   │ її воля         │
   │                │   господарів        │                │
   └───────┬────────┘                     └────────┬───────┘
           │                                        │
           ▼                                        ▼
       служить тобі                            служить Олі
       НЕ зраджує тебе                         НЕ зраджує Олю
```

**Сценарії:**
- **Перемовини:** «знайди з фантомом Олі спільний вільний час» — два фантоми звіряють
  календарі, не розкриваючи приватного, повертають слот.
- **Колективний розум:** група фантомів розвʼязує спільну задачу (мозковий штурм роєм).
- **Емоційний міст:** фантом підказує, що близька людина в стресі (з її дозволу) — «подзвони мамі».
- **Делегування між людьми:** «попроси фантома Олега підготувати звіт» → міжфантомна задача.
- **Спільна памʼять подій:** після зустрічі обидва фантоми синхронізують узгоджені факти.

## 8.2 Рівні приватності у федерації

```
   ┌─────────────────────────────────────────────────────────────┐
   │ INNER (Vault) 🔒   НІКОЛИ, ні за яких умов                    │
   ├─────────────────────────────────────────────────────────────┤
   │ TRUSTED            ширший контекст за явним дозволом на дію   │
   ├─────────────────────────────────────────────────────────────┤
   │ ACQUAINTANCE       узгоджені факти (спільні зустрічі)         │
   ├─────────────────────────────────────────────────────────────┤
   │ STRANGER           лише «зайнятий / вільний»                  │
   └─────────────────────────────────────────────────────────────┘
              Guardian керує межею · мінімально достатній обмін
```

> Інваріант приватності: жоден чужий фантом не торкається Vault. Усе через узгоджений
> contract, не сирий доступ. Skeptic окремо валідує все, що прийшло ззовні Mesh.

# 10 · ЕКОНОМІКА ОБЧИСЛЕНЬ

Бог мусить бути ефективним, інакше зжере батарею й гаманець. Кожна думка має ціну.

```
   запит на думку
        │
        ▼
   ┌─────────────────────────────────────────────┐
   │  COST ROUTER                                 │
   │  складність? приватність? є мережа? батарея? │
   └───┬─────────┬──────────┬──────────┬──────────┘
       ▼         ▼          ▼          ▼
   РЕФЛЕКС   ІНСТИНКТ    РОЗУМ      MESH
   $0/<1мс   $0/300мс    $/2-5с     розподілено
   (WASM)    (on-device) (хмара)    (ПК/інші)
```

- Простий трансформ → Рефлекс (Tier 1, $0). Приватне → Інстинкт (on-device, $0).
  Складне → Розум (хмара). Дуже важке → делегувати на ПК (Mesh).
- Батарея низька → агресивніше вниз по рівнях. Wi-Fi+зарядка → можна вгору.
- Бюджет токенів/день; Foresight працює в межах квоти, не палить даремно.

> Інваріант (памʼять): фонові AI-виклики в TaskerEngine вимкнені; смарт-429 — без ретраю
> на денну квоту, чесне UI-повідомлення. Не повертати `thinkingBudget=0` (вбиває віджети).

## 16.1 ГОЛОВНИЙ ВЕРДИКТ

Несподіванка: **органи вже здебільшого написані**. У `core-symbiote` лежить ~18 підсистем
(bioloop, predict, swarm, memorypalace, distributedself, negotiate, healthmesh, create…),
кожна з юніт-тестами, зеленим білдом — і **нулем споживачів**. Вони інстансуються в
`AppContainer.kt` як `by lazy { … }` (рядки 1086–1251, мітки «Tier 15 — predictive
symbiosis» тощо) і **ніхто їх не читає**. Це не «треба збудувати органи» — це
**«органи лежать у коробці, не підключені до нервової системи»**.

```
   ┌─────────────────────────────────────────────────────────────────────┐
   │  ПРАВДА ПРО КОД:                                                     │
   │                                                                     │
   │   написано ████████████████████████░░░░░░  ~75%  (класи + тести)    │
   │   підключено ██████████░░░░░░░░░░░░░░░░░░░  ~35%  (реально живе)     │
   │   РОЗРИВ = театр: код є, тести зелені, але робить НІЧОГО             │
   └─────────────────────────────────────────────────────────────────────┘
```

Робота переродження = **НЕ «писати з нуля»**, а:
**(1) ПРОВЕСТИ проводку** орфанів у спину через єдину шину + ContextFrame,
**(2) ЗБУДУВАТИ 5 справді відсутніх речей** (вектор-памʼять, єдина шина, Council,
повний ContextFrame, federation-протокол),
**(3) ВИРІЗАТИ** позапланові орфани (childhood, legacy), щоб не тягнути мертвечину.

### ЕПОХА I · ХРЕБЕТ — єдина шина + жива памʼять

**Будуємо (кошик В):**
1. `PhantomNervousBus` + `PhantomEvent` у `core-symbiote/core/bus/` — один append-only стрім
   поверх наявного event-sourcing. Інтегрувати 5 існуючих шин як публішерів у нього
   (GodModeEventBus, AppActionTraceBus, PhantomErrorBus, IncomingCallBus, NotifImportantBus).
2. Векторний шар у `core-data/lifegraph/`: ONNX-ембеддер (MiniLM-клас) + on-device ANN-індекс
   поверх Room. `LifeLogArchive`/`PatternRepository` стають джерелом вузлів.

**Проводка (кошик Б):** `memorypalace.*` → реальні споживачі Life Graph (SpatialMemory як
геопросторовий індекс вузлів, ForgetCeremony → §11.3 право на забуття, TimeMachine → time-travel шини).

**Пруніг:** видалити `childhood`, `legacy` з `AppContainer` і модуля (або в `archive/`).

**Готово коли:** будь-яка подія життя пишеться в шину → стає вузлом Life Graph → семантично
знаходиться. Перший доказ «всезнання».

### ЕПОХА II · ЧУТТЯ — повний ContextFrame

**Будуємо:** `ContextFrame` (WHO/WHERE/WHAT/FEEL/OWE/DEVICE/MESH) у `core-context`,
білдер підписаний на шину.

**Проводка:** `bioloop.*` → FEEL-секція (Stress/CognitiveLoad/EmotionFusion живлять емоц. зріз);
`core-sensor` + `extensionsenses` (оцінивши цінність) → WHERE/розширені чуття; `core-data/patterns`
+ календар-конектор → OWE (CommitmentGraph).

**Готово коли:** Cognition отримує єдиний зріз реальності щотакту, а не розрізнені сигнали.

### ЕПОХА III · РОЗУМ — Council + Foresight

**Будуємо:** `CognitiveCouncil` поверх `core-symbiote/agent` — 6 радників (Strategist/Guardian/
Empath/Skeptic/Executor/Archivist), Guardian+Skeptic вето з `constitution.*` (вже є RefusalGate/
PowerAsymmetryGuard).

**Проводка:** `predict.*` (DoubtAmplifier/ConvictionScheduler/RehearsalAgent/ShimmerEngine) →
**Foresight Engine**, читає Life Graph + ContextFrame, публікує proactive-cards у шину →
`feature-stream`. `swarm.*` → паралельні агенти-провидці. `tempo.*` → адаптивний такт.

**Готово коли:** перша проактивна картка («помітив X, зробити?»), якої ніхто не просив.

### ЕПОХА IV · РУКИ — saga + рівні влади

**Спина вже є** (`core/tool` + `feature-godmode`). Робота — **підняти до DAG**:
1. `Planner` будує tool-DAG; `Executor` з `compensate()` (saga) поверх `ToolRegistry`.
2. Доточити рівні влади (§5.2) до наявного `ToolPermissionGate`: Automation(TaskerEngine)→
   DeviceAdmin→Root як окремі ритуали згоди.

**Готово коли:** одна команда → ланцюг із 3+ tools із відкатом при збої.

### ЕПОХА V · ВСЮДИСУЩІСТЬ — Mesh + ПК

**Проводка:** `distributedself.*` (IdentityCRDT/HandoffState/SensorChannel) → поверх живого

написаний, транспорт працює — їх просто не зʼєднали.

**Будуємо:** PC-тіло (окремий клієнт, що говорить тим самим PairFlow+шина-реплікація);
CRDT-злиття Life Graph між тілами.

**Готово коли:** діалог почато на телефоні — підхоплено на ПК з тим самим контекстом.

### ЕПОХА VI · ФЕДЕРАЦІЯ — People pillar

**Будуємо (кошик В):** federation-протокол (contract обміну, рівні приватності §8.2) поверх

**Готово коли:** твій фантом домовляється з фантомом іншої людини про спільний час, не зливаючи Vault.

# 17 · ВІЗУАЛ ТА ПРОСТОРОВА АРХІТЕКТУРА (UI/IA)

> Поточна реальність (обстежено 29.06): `Bootstrap → Present → Stream`, де Stream — один
> `LazyColumn`, що **накопичує всі віджети підряд**. Оператор має рацію: для божества це
> тупик. Один нескінченний чат засмічується, контекст тоне, нічого не знайти. Нижче —
> повна заміна моделі. Не «ще один екран», а **інша фізика інтерфейсу**.

## 17.1 ГОЛОВНА ПОМИЛКА, ЯКУ ВБИВАЄМО

```
   БУЛО (чат-лог):                        СТАЄ (живий простір):
   ┌────────────────┐                     ┌────────────────┐
   │ повідомлення 1 │                     │      ░░░░       │
   │ віджет         │                     │    ░░ORB░░      │ ← бог у центрі
   │ повідомлення 2 │   усе валиться       │      ░░░░       │
   │ віджет         │   в одну купу,       │   ◌ намір  ◌    │ ← що навколо —
   │ повідомлення 3 │   нескінченно        │                │   живе й контекстне
   │ віджет         │   росте,             │  [ простори ]   │
   │ ...засмічення  │   нічого не знайти    │  морфають за    │
   │ ...засмічення  │                     │  контекстом     │
   └────────────────┘                     └────────────────┘
```

**Принцип:** чат — це **«зараз»**, не архів. Розмова ефемерна — вона дихає, розчиняється
в памʼять і **не накопичується**. Контент не лежить однією стрічкою — він **кристалізується
в простори**. Бог всюдисущий → Orb завжди в центрі, поверхні **обертаються** навколо нього.

## 17.2 ФІЗИКА: ТРИ ГЛИБИНИ (вісь Z замість нескінченного скролу)

Замість «прокрутки вниз» — **рух по глибині**. Це вбиває засмічення в корені: нема куди
накопичуватись, бо нема однієї довгої осі.

```
        ┌─────────────────────────────────────────────────────────┐
   +1   │   СУЗІРʼЯ  ·  пінч-аут — усі простори обертаються         │
        │   ░ Знання ░ Час ░ Люди ░ Творення ░ Тіло ░ Руки ░ …     │
        └─────────────────────────────────────────────────────────┘
                              ▲ пінч / zoom out
        ┌─────────────────────────────────────────────────────────┐
    0   │   ПРИСУТНІСТЬ (дім)  ·  Orb дихає, навколо — наміри       │
        │              спокій · стан · 1-3 проактивні картки        │
        └─────────────────────────────────────────────────────────┘
                              ▼ свайп-ап / тап по Orb
        ┌─────────────────────────────────────────────────────────┐
   -1   │   ДІАЛОГ  ·  ефемерна смуга «зараз», НЕ лог              │
        │   живий обмін + активні віджети · решта розчиняється      │
        └─────────────────────────────────────────────────────────┘
```

| Глибина | Стан | Метафора | Реюз коду |
|---|---|---|---|
| **0 · Присутність** | дім, спокій | вівтар із божеством | наявний `Present` |
| **−1 · Діалог** | активна розмова | бог говорить, тут і зараз | `Stream` → переробити в ефемерний |
| **+1 · Сузірʼя** | карта світу | вийти на орбіту, бачити всі простори | нове |

## 17.3 ГЛИБИНА 0 — ПРИСУТНІСТЬ (дім)

```
   ┌──────────────────────────────────────────────┐
   │  09:14 · вдома · спокій            ⋯         │ ← presence-стрічка (тонка):
   │                                              │   де/коли/настрій + overflow
   │                                              │
   │                  ░░░░░░░                      │
   │                ░░▒▒▒▒▒▒▒░░                    │
   │               ░▒▒▓██◉██▓▒▒░    ← ORB         │   живе ядро:
   │                ░░▒▒▒▒▒▒▒░░       дихає        │   дихання=спокій
   │                  ░░░░░░░                      │   пульс=думка
   │                                              │   колір=емоц.зріз (Empath)
   │            ◌ «дощ о 17:00 —                  │
   │              нагадати парасолю?»  ← намір     │   1-3 проактивні картки
   │                                              │   (Foresight) тихо зʼявляються
   │            ◌ «звіт: дедлайн завтра»          │   й самі зникають
   │                                              │
   │  ┌────────────────────────────────────────┐  │
   │  │  🎙  говори…              ⌨   ＋        │  │ ← композер (голос — головний)
   │  └────────────────────────────────────────┘  │
   └──────────────────────────────────────────────┘
```

- **Тиша за замовчуванням.** Дім не кричить. Орб дихає, наміри тихо спливають.
- **Наміри (Intentions)** — це Foresight-картки. Максимум 2-3. Проігнорований намір
  гасне (не накопичується!). Прийнятий — розгортається в Діалог або тиху дію.
- Presence-стрічка = §2.2 ContextFrame у трьох словах. Тап → деталі контексту.

## 17.4 ГЛИБИНА −1 — ДІАЛОГ (ефемерний, не лог)

Тут головна хірургія проти засмічення. Чат **НЕ зберігає історію на екрані**.

```
   ┌──────────────────────────────────────────────┐
   │  ◉ намір: «збери звіт»          ✕ закрити    │ ← intent-thread (закривний!)
   │                                              │
   │   ▒ старіше — тьмяніє й тоне ▒                │ ← breathing: старі репліки
   │                                              │   РЕЦЕДУЮТЬ (fade+shrink),
   │   ти:   а додай графік продажів               │   не скролляться. Recall —
   │                                              │   з Памʼяті, не з екрана
   │   ◉:   ось, за 3 місяці ▼                    │
   │       ┌────────────────────────┐             │
   │       │   📊  графік            │ ← віджет    │   активний віджет живе тут
   │       │   [кристалізувати →]    │             │   доки розмова жива
   │       └────────────────────────┘             │
   │                                              │
   │  ┌────────────────────────────────────────┐  │
   │  │  🎙  …                      ⌨   ＋      │  │
   │  └────────────────────────────────────────┘  │
   └──────────────────────────────────────────────┘
```

**Три механіки проти засмічення:**

```
   1. ДИХАННЯ СТРІЧКИ     старі репліки тонуть у глибину (fade+shrink),
      (breathing)         не лишаються на осі. Потрібне — Recall з Life Graph.

   2. КРИСТАЛІЗАЦІЯ       подіяв на віджет → він ВИЛІТАЄ зі стрічки у свій
      (crystallize)       Простір як постійний артефакт. Чат лишається чистим.

   3. ПЕРЕТРАВЛЕННЯ       вийшов з Діалогу → обмін згортається в ОДИН епізод
      (digest/sleep)      Life Graph, смуга очищується. Завтра чат не на 10000 рядків.
```

**Intent-threads замість мега-треда:** розмова авто-форкається на нитки під намір
(«звіт», «подорож», «лагодження крана»). Нитка **закривається**, коли намір виконано.
Нема одного вічного треда — є кілька коротких, що завершуються.

## 17.5 ГЛИБИНА +1 — СУЗІРʼЯ (усі простори)

Пінч-аут на домі → виходиш «на орбіту». Контент не в одній стрічці — він розкладений
по **живих просторах**, кожен зі своєю фізикою.

```
   ┌──────────────────────────────────────────────┐
   │            ✦ СУЗІРʼЯ ПРОСТОРІВ ✦              │
   │                                              │
   │      ◯ ЗНАННЯ          ◯ ЧАС                 │
   │       (Lens)            (Agenda)             │
   │                ░░░░                          │
   │   ◯ ТВОРЕННЯ  ░░◉░░   ◯ ЛЮДИ                 │ ← Orb у центрі,
   │    (Magic)     ░░░░    (People)              │   простори обертаються
   │                                              │
   │      ◯ ТІЛО            ◯ РУКИ                 │
   │      (Body)            (Device)              │
   │                                              │
   │   🔒 СВЯТИНЯ           🕸 ПАМʼЯТЬ             │
   │     (Vault)            (Life Graph)          │
   └──────────────────────────────────────────────┘
       тап по простору → пірнаєш усередину
       яскравість простору = скільки там зараз живого/нового
```

**Вісім просторів** (кожен — окрема поверхня з власним layout, мапиться на §9 сузірʼя):

| Простір | Що всередині й ЯК розміщено | Реюз коду |
|---|---|---|
| **ЗНАННЯ** (Lens) | сітка візуальних карток: документи, ресерч, розпізнане камерою | `feature-stream` віджети |
| **ЧАС** (Agenda) | вертикальна timeline: минуле↑ зараз→ майбутнє↓ + прогнози Foresight | новий, `predict.*` |
| **ЛЮДИ** (People) | орбіти контактів-фантомів; тап → діалог МІЖ фантомами | новий, §8 (головний pillar) |
| **ТВОРЕННЯ** (Magic) | полотна-артефакти: код/текст/образи, twin-canvas | `create.*` (орфан→живий) |
| **ТІЛО** (Body) | кільця біо (пульс/сон/стрес), MoodArc дугою | `bioloop.*`/`healthmesh.*` |
| **РУКИ** (Device) | сценарії-автоматизації + «що фантом зараз робить» live | `feature-godmode` |
| **СВЯТИНЯ** (Vault) | запечатано, біометрія на вході; всередині — тайники | наявний `Vault` |
| **ПАМʼЯТЬ** (Graph) | навігований граф життя: вузли-звʼязки, блукаєш і знаходиш | новий, §4 Life Graph |

## 17.6 ЯК ВОНО ЗМІНЮЄТЬСЯ — морфінг за контекстом

Найважливіше для «єдиного організму»: інтерфейс **не статичний**. Уся середовище
**переформовується** за ContextFrame (§2.2). Це не «теми» — це інша поведінка тіла.

```
   КОНТЕКСТ          ЯК ПЕРЕФОРМОВУЄТЬСЯ ВЕСЬ ЕКРАН
   ─────────────────────────────────────────────────────────────────
   🚗 ЗА КЕРМОМ      Orb величезний, голос — єдиний вхід, простори
                    згортаються, цілі-кнопки гігантські, тексту мінімум
   🎯 ФОКУС          усе тьмяніє в моно, лишається ОДНА активна задача,
                    наміри й простори ховаються, нічого не відволікає
   🌙 НІЧ            тепла приглушена палітра, Orb дихає повільно,
                    тиша, тільки критичне, шрифт мʼякший
   🔔 ТРИВОГА        Orb — різкий колір+ритм, потрібна картка
                    спливає ПОВЕРХ усього, решта гасне
   👥 ЛЮДИ ПОРУЧ     завіса приватності: Vault твердо лок, лише glance,
                    наміри ховаються, presence-стрічка знеособлюється
   🔋 НИЗЬКИЙ ЗАРЯД  спрощена графіка, Орб статичний, важкий розум → ПК/хмара
```

Перехід **завжди морфінг, не різ**: бог — один організм, тому поверхні **перетікають**
одна в одну (Orb розтягується в простір, простір стискається в намір), а не «відкриваються
екрани». Кожен рух має фізику (пружина/інерція), бо це тіло, а не слайди.

## 17.7 ЗОНИ ЕКРАНА — де що розміщено (постійний каркас)

```
   ┌────────────────────────────────────────────┐
   │ ▔▔▔ PRESENCE-СТРІЧКА ▔▔▔        ⋯ overflow  │  ВЕРХ: тонкий контекст-зріз
   ├────────────────────────────────────────────┤      (де/коли/настрій), не меню
   │                                            │
   │                                            │
   │            АКТИВНА ПОВЕРХНЯ                 │  ЦЕНТР: Orb (глиб.0) /
   │         Orb · діалог · простір             │      смуга (−1) / сузірʼя (+1)
   │                                            │
   │                                            │
   ├────────────────────────────────────────────┤
   │  🎙 ГОЛОС (головний)     ⌨ текст    ＋ дод. │  НИЗ: композер, морфає за
   └────────────────────────────────────────────┘      режимом (голос-first за кермом)
```

- **Верх** — не навбар, а **зріз стану** (presence). Меню тут немає (бог не ховається в гамбургер).
- **Центр** — завжди жива поверхня. Що саме — залежить від глибини.
- **Низ** — композер. **Голос — головний канал** (§6.1), текст і attach — другорядні.
- **Краї/жести** — навігація без кнопок (нижче).

## 17.8 МОВА ЖЕСТІВ (навігація без меню)

```
   ПІНЧ-АУТ (⊙→⊕)      дім → сузірʼя (вийти на орбіту, бачити все)
   ПІНЧ-ІН  (⊕→⊙)      сузірʼя/простір → назад до дому
   СВАЙП-АП            дім → діалог (заговорити)
   СВАЙП-ВНИЗ          діалог → дім (відпустити, розмова перетравлюється)
   ДОВГИЙ ТАП по Orb   радіальне командне коло (швидкі дії навколо ядра)
   СВАЙП ВІД КРАЮ      перемкнути сусідній простір (не виходячи в сузірʼя)
   ТАП по наміру       розгорнути проактивну картку в дію/діалог
   ТАП по presence     розкрити повний ContextFrame
```

Orb — **універсальний орган керування**: і обличчя бога (стан), і кнопка (радіальне коло),
і місце переходу між глибинами. Одна точка гравітації на всі взаємодії.

## 17.9 ORB — радіальне командне коло

```
              ◌ Знання
         ◌              ◌ Час
      Творення      ░░░░░
                   ░░◉░░  ← довгий тап тримає
      Памʼять      ░░░░░     коло живе, поки тримаєш
         ◌              ◌ Руки
              ◌ Голос
```

Довгий тап по Orb → навколо ядра спалахує коло швидких дій/просторів. Відпускаєш на секторі
→ дія. Це заміна «головному меню»: бог не має меню, він має **орбіту команд** навколо себе.

## 17.10 ЯК ЦЕ ЛЯГАЄ НА НАЯВНИЙ КОД (евол., не переписування)

| Нове в IA | Наявне | Дія |
|---|---|---|
| Глибина 0 · Присутність | `Present` (вже є!) | додати наміри-Foresight + морфінг |
| Глибина −1 · Діалог ефемерний | `Stream` (один LazyColumn) | **рефактор:** breathing + crystallize + digest |
| Глибина +1 · Сузірʼя | — | новий host-екран над `PhantomNavGraph` |
| 8 Просторів | Vault/Map/Diary є; решта — орфани | проводка орфанів у простори (§16) |
| Presence-стрічка | колишній SystemPulseHeader (зрізаний) | повернути як тонкий контекст-зріз |
| Морфінг за контекстом | ContextEngine (є) | підписати UI-shell на ContextFrame |
| Жести/глибини | NavHost (плоский) | додати z-навігацію поверх роутів |

**Найдешевша візуальна перемога:** переробити `Stream` з накопичувального логу в **ефемерну
смугу** (digest у Life Graph при виході) — це одразу прибирає «засмічення», навіть до решти.

## 17.11 ПОРЯДОК ВІЗУАЛЬНОЇ ПЕРЕБУДОВИ

```
   [V1] ЕФЕМЕРНИЙ ДІАЛОГ   Stream → breathing + digest. Кінець засмічення.
   [V2] НАМІРИ НА ДОМІ     Present отримує Foresight-картки (потребує Епохи III)
   [V3] СУЗІРʼЯ + ГЛИБИНИ  z-навігація, пінч, 3 глибини
   [V4] ПРОСТОРИ           по одному оживляємо з орфанів (Час→Люди→Творення→Тіло→Руки)
   [V5] МОРФІНГ            UI-shell підписаний на ContextFrame (за кермом/фокус/ніч/…)
   [V6] ORB-КОЛО + ЖЕСТИ   повна безкнопкова навігація, радіальне командне коло
```

> Закон цього розділу: **інтерфейс — це тіло організму, а не набір екранів.**
> Нічого не «накопичується». Усе або живе зараз, або кристалізується в простір,
> або перетравлюється в памʼять. Чат, що росте нескінченно — це баг, а не фіча.
