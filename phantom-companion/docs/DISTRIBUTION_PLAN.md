# Розповсюдження, захист і власність

Ухвалено 2026-08-10. Власник: Кирило Милосердов.

Причина розвороту: Play вимагає юрособи/фінансових умов, яких зараз немає.
Тому **свій канал стає основним**, а Play — пізнішим додатком, не умовою запуску.

---

## 1. Захист: чому замок не в застосунку

Клієнт зламати можна завжди. Тому платне має бути **не кодом, а даними, яких
у зламаної копії немає**.

| Рівень | Що це | Чи ламається на пристрої |
|---|---|---|
| **Дані під ключем** ★ | Густий пак Києва, голосові моделі, транспорт, 3D-місто — качаються з R2 за підписаним URL, який видає ліцензійний сервер | **Ні.** Патч клієнта не створює даних |
| Сертифікат Ed25519 | Права доводить підпис; приватного ключа в APK немає | Ні (можна лише вирізати перевірку) |
| Прив'язка до пристрою | `device_fingerprint` у сертифікаті | Ні |
| Політика + `min_build` | Гасить старі збірки й окремі копії | Ні (підпис) |
| Нативний вартовий (NDK) | Перевірка підпису APK і контрольної суми dex у C++ | Важко, але можна |
| R8 + шифрування рядків | Прибирає імена й адреси | Затримка |
| Виявлення Frida/root | Ознака, не стіна | Обходиться |

**Порядок робіт:** дані під ключем → нативний вартовий → шифрування рядків →
детектори. Перший пункт коштує найменше й дає найбільше.

### Що робить «дані під ключем» на практиці
1. Пак лежить у R2 приватно.
2. Клієнт просить `POST /api/pack` зі своїм сертифікатом.
3. Сервер перевіряє підпис + рівень + відбиток → віддає presigned URL на 15 хв.
4. Клієнт качає й перевіряє Ed25519-підпис самого паку.

Зламана копія не проходить крок 3. Поділившись паком, людина ділиться файлом
на сотні мегабайт, а не ключем — і наступний пак усе одно не отримає.

## 2. Власність і апеляції

Мета: щоб у будь-якому спорі документи були на твоєму боці **до** спору.

1. **Свідоцтво про реєстрацію авторського права** (УКРНОІВІ, ~1–2 тижні,
   кілька сотень грн). Це головний документ; його приймають і суди, і Google,
   і грантодавці. Подається на вихідний код як твір.
2. **Часові мітки коду.** Git з підписаними комітами + OpenTimestamps на хеш
   релізу. Безкоштовно, доводить «я мав це раніше».
3. **`LICENSE`** — уже є, закрита, з іменем правовласника.
4. **Торгова марка** на назву/знак — окремо, коли буде юрособа.
5. **Журнал релізів**: кожен реліз = тег + хеш AAB/APK + дата. Це доказ
   безперервності авторства.
6. **Договір з кожним, хто торкнеться коду** (якщо колись буде команда) —
   передача майнових прав, інакше вони за замовчуванням у виконавця.

## 3. Кабінет і канал розповсюдження

### Архітектура
```
Сайт (Netlify)  ─── кабінет ──→  Ліцензійний сервер (FastAPI)
                                    │  ключі, активації, політика,
                                    │  підпис сертифікатів (Ed25519)
                                    ↓
                                 Supabase (Postgres + Auth)
                                    │  акаунти, покупки, передача ключів
                                    ↓
                                 Cloudflare R2
                                    збірки APK/PC + паки даних
                                    (приватно, presigned URL)
```

**Ключ лишається перепусткою в застосунку** (нуль конфігу). Акаунт потрібен
лише в кабінеті — щоб купити, побачити свої ключі, передати, зняти пристрій.

### Що вміє кабінет
- вхід (Supabase Auth, magic link — без паролів)
- мої ключі: рівень, активації, вікно оновлень, відкликати пристрій
- **передати ключ** іншій людині (одна кнопка, лог передачі)
- купити ще (LemonSqueezy → вебхук уже написаний)
- **завантажити застосунок**: Android APK + ПК, лише свіжа версія, лише за
  дійсним ключем (або вільна збірка для вільного рівня)
- історія збірок і що змінилось

### Оновлення без Play
Свій канал = свої оновлення. Клієнт раз на добу питає
`GET /api/build/latest`, і якщо номер більший — качає APK з R2 і **перевіряє
Ed25519-підпис файлу перед установкою**. Без цієї перевірки канал оновлень
сам стає діркою.

## 4. Рівні доступу в застосунках

Ворота вже є (`core-license`), замків ще не поставлено: `LicenseService.has`
не має жодного виклику, тож сьогодні кожна копія має весь список. Це наступна
хвиля, а не стан рівнів.

`LicenseModel.DEFAULT_FREE` — шість прав: `core.chat` (розмова разом із її
шифруванням), `core.map`, `core.nav`, `core.alerts` (тут же попередження про
підміну GNSS), `core.vault`, `core.voice`. Особистий додає рівно шість:
`bridge.pair`, `memory.longterm`, `map.terrain3d`, `voice.premium`,
`gnss.blackbox` (лише запис і розбір польотів — жива тривога лишається
вільною), `export.reports`. Екіпаж = Особистий + `crew.sync`; Підрозділ =
Екіпаж + `fleet.onprem`.

**Підлога, яку не звузити ніколи:** усі шість вільних прав. `LicenseGate`
рахує `policy.free + DEFAULT_FREE` — об'єднання, а не заміну, тож сервер може
вільний рівень лише РОЗШИРИТИ. Обіцянка, яку відкликає серверний push, — не
обіцянка; і було збочено, що пристрій, який ніколи до нас не достукався,
лишався з чатом, а той, що достукався, міг його втратити.
`/admin/policy` тепер відхиляє `free` без котрогось із шести, бо мовчазна
пустушка лишила б власника з вірою, що він щось забрав.

Закріплено `SafetyFloorFirewallTest`: окремо `SAFETY_FLOOR` (мапа, навігація,
тривоги, сховище) — про них код взагалі не сміє питати ліцензію; окремо
`DEFAULT_FREE` — рівність шістці й точний склад платної шістки.

## 5. Що потрібно від власника

**Supabase** (у файл `platform-site/server/.env`, не в чат):
```
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_ANON_KEY=…        # публічний, іде в сайт
SUPABASE_SERVICE_KEY=…     # СЕКРЕТ, лише сервер
SUPABASE_DB_URL=postgresql://…   # connection string, Session pooler
```

**Cloudflare R2** (туди ж):
```
R2_ACCOUNT_ID=…
R2_ACCESS_KEY_ID=…
R2_SECRET_ACCESS_KEY=…
R2_BUCKET=phantom-dist
R2_PUBLIC_HOST=…           # якщо буде свій домен для публічних файлів
```

**Ніколи не в Supabase і не в браузер:** приватний ключ підпису ліцензій
(`platform-site/server/keys/signing.pem`) і релізний keystore. Вони живуть
тільки на сервері й на твоїй машині.

Ще потрібно: де хоститься ліцензійний сервер (зараз домену
`license.phantom-os.dev` не існує) — Fly.io / Railway / VPS.

## 6. Порядок

1. **Захист даними** — паки під ключем + `/api/pack` + перевірка підпису паку.
2. **Кабінет** — Supabase Auth, мої ключі, передача, завантаження з R2.
3. **Оновлення без Play** — свій канал із перевіркою підпису APK.
4. **Нативний вартовий** — NDK-перевірка підпису.
5. **Авторське право** — подача до УКРНОІВІ.
6. **Мапа** — п'ять хвиль за `docs/MAP_MONTH_PLAN.md`, тепло першим.

Мапа йде паралельно як основна продуктова робота: захист і кабінет — це те,
без чого не можна продавати, а мапа — те, за що платитимуть.
