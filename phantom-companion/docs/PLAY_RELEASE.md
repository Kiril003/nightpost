# Вихід у Google Play і захист збірки

Власник і правовласник: Кирило Милосердов. Ліцензія закрита (`LICENSE`).

## Частина 1. Наскільки застосунок захищений

Чесно, без реклами:

**Абсолютного захисту клієнта не існує.** Хто має APK і час, той вирізає
будь-яку перевірку всередині нього. Тому гроші захищає не обфускація, а те,
чого в APK немає — приватний ключ підпису сертифікатів.

Що вже стоїть:

| Рубіж | Що робить | Чого не робить |
|---|---|---|
| Ed25519-сертифікат | Права доводить підпис сервера; у застосунку лише **публічний** ключ | Не заважає патчити перевірку локально |
| Прив'язка до пристрою | Сертифікат несе `device_fingerprint`; на іншому телефоні недійсний | Не рятує від емулятора з підміненим ANDROID_ID |
| Відкликання | `/admin/revoke` → ключ мертвий на наступному зв'язку | Не діє на копію, яку тримають вічно офлайн |
| Підписана політика | `min_build` гасить платні права у старих збірках; `blocked` — поіменно | Підроблена політика не приймається (перевіряється підписом) |
| `IntegritySentry` | Ловить чужий підпис APK, sideload store-збірки, debuggable | Обходиться патчем — це затримка, не стіна |
| R8 + `isMinifyEnabled` | Прибирає імена, ускладнює пошук місця для патча | Не шифрує логіку |
| Реліз-ключ поза git | Ніхто не випустить оновлення, яке Android прийме як наше | Нічого, якщо ключ витече — тому він і не в репозиторії |

**Що дає найбільше при найменших витратах — Play Integrity API.** Він
перевіряє на серверах Google, що збірка справжня, зі справжнього Play і на
несфальсифікованому пристрої. Вмикати варто після першого релізу: вердикт
приходить у наш `/api/activate`, і активація перепакованої копії не
відбувається взагалі — на пристрої вирізати нічого.

**Головний висновок для моделі:** ми продаємо безстрокову ліцензію на ядро
плюс вікно оновлень. Зламана стара збірка — це втрачена одна копія, а не
втрачений продукт: `min_build` робить її мертвою для платних функцій, щойно
вийде наступна версія.

## Частина 2. Як вивести в Play

### 2.1 Що потрібно, чого ще немає

- [ ] **Обліковий запис розробника** — $25 одноразово, developer.android.com.
      Для приватної особи потрібен паспорт; для ТОВ — виписка (те саме
      питання юрособи, що й у грантах).
- [ ] **Політика конфіденційності за URL** — Play не пускає без неї.
      На сайті вже є `/privacy`; посилання йде в консоль.
- [ ] **Розділ Data safety** — заповнюється вручну в консолі. Наша відповідь
      проста і рідкісна: дані не покидають пристрій; винятки — тайли мап,
      сервер ліцензій, повітряні тривоги.
- [ ] **Скріншоти** (мін. 2, телефон) + іконка 512×512 + банер 1024×500.
- [ ] **Ключ підпису** — `keystore.properties` (див. нижче).

### 2.2 Створити ключ підпису (один раз, назавжди)

```bash
keytool -genkeypair -v -keystore ~/phantom-release.jks \
  -alias phantom -keyalg RSA -keysize 4096 -validity 10000
```

Потім у корені `phantom-companion/keystore.properties` (у git не потрапляє):

```properties
storeFile=/home/kyrylo/phantom-release.jks
storePassword=…
keyAlias=phantom
keyPassword=…
signatureSha256=…
```

`signatureSha256` береться з:

```bash
keytool -list -v -keystore ~/phantom-release.jks -alias phantom \
  | grep 'SHA256:' | head -1 | tr -d ' :' | sed 's/SHA256//' | tr 'A-Z' 'a-z'
```

**Втрата цього файлу = втрата застосунку.** Оновлення підписані іншим ключем
Android не приймає. Копія — в офлайн-сховище, не в хмару.

> Якщо ввімкнути Play App Signing (за замовчуванням), Google перепідписує APK
> своїм ключем. Тоді `signatureSha256` треба брати **з консолі Play**
> (Setup → App signing → SHA-256 of app signing certificate), інакше
> `IntegritySentry` вважатиме магазинну збірку чужою.

### 2.3 Зібрати те, що Play прийме

```bash
./scripts/play-release.sh 2        # 2 = versionCode
```

Скрипт: перевіряє наявність ключа, збирає `storeRelease` AAB, друкує підпис і
розмір, нагадує про `min_build`.

Store-збірка (`productFlavors.store`) уже роздягнена від усього, що Play
відхиляє: Accessibility-нагляд, читання сповіщень, фільтрація дзвінків,
`QUERY_ALL_PACKAGES`. Польова збірка (`field`) лишається для sideload і в
магазин не їде.

### 2.4 Перше завантаження

1. Play Console → Create app → назва, українська як типова мова.
2. Internal testing → завантажити AAB → додати себе в тестувальники.
3. Заповнити: Data safety, Content rating (анкета), Target audience, Privacy
   policy URL, Ads = ні.
4. Внутрішній тест триває, поки не набридне; далі Closed → Production.

### 2.5 Що очікувано спитають

- **Локація у фоні** — це найчастіша причина відмови. Потрібне відео, де
  видно, навіщо (супровід маршруту з вимкненим екраном). Якщо не хочеться
  боротись — можна прибрати `ACCESS_BACKGROUND_LOCATION` зі store-збірки й
  лишити супровід лише при відкритому застосунку.
- **Мікрофон** — пояснити, що розпізнавання локальне (Vosk на пристрої).
- **Foreground service types** — уже оголошено; Play перевіряє відповідність.

## Частина 3. Важіль над уже завантаженими копіями

Це те, заради чого писався `core-license`. Ввести платні рівні можна після
роздачі — не міняючи APK у людей.

```bash
# Звузити вільний рівень і відсікти всі збірки, старіші за 12-ту
curl -X POST https://license.phantom-os.dev/admin/policy \
  -H "X-Admin-Token: $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"free":["core.map","core.nav","core.alerts","core.vault"],
       "min_build":12,
       "notice":"Чат і голос тепер у платному рівні."}'

# Погасити конкретну ліцензію
curl -X POST …/admin/revoke -H "X-Admin-Token: $ADMIN_TOKEN" \
  -d '{"license_id":"…","reason":"повернення коштів"}'
```

Політика підписана тим самим Ed25519-ключем, тож підмінити її на шляху
неможливо: застосунок приймає лише документ, підпис якого сходиться з
`LICENSE_PUBLIC_KEY`, вшитим у збірку.

**Межа важеля, закріплена тестом:** нижче за мапу, навігацію, тривоги й
сховище звузити не можна. `LicenseGate` домішує цю підлогу назад незалежно
від того, що каже політика (`LicenseGateTest.the free set can be narrowed for
everyone but never below safety`).
