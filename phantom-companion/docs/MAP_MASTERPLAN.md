# PHANTOM MAP — МАЙСТЕР-ПЛАН «ЖИВА МАПА»

> Карта як просторовий орган PHANTOM, а не переглядач.
> Бачення → закони → сотні можливостей (логіка + візуал + реалізація + агентність) → дорожня карта.
> Мова: українська для оператора, технічні терміни англійською. Усі дані — **keyless / безкоштовні / offline-first** де можливо.
>
> Цей документ поглинає `MAP_ROADMAP.md` / `MAP_PHASES.md` і розширює їх як «R4+ / MAP-∞».
> Живий стан виконання — у `MAP_MASTERPLAN_PROGRESS.md`.

## 0. КОНТЕКСТ І ПРОБЛЕМА

Оператор попросив «мапу рівня Фантом», а отримав сірий сухий переглядач. Зроблено фікси (темний стиль, емодзі-POI, перемикач базового стилю, пульсуючий орб, робоча «Зберегти у Vault»), але **функціонально мапа лишилась пасивною**: вона показує, але майже нічого не *робить* і PHANTOM нею не *керує*.

Ціль — перетворити мапу на **живий, агентний, адаптивний просторовий інтелект**, яким однаково володіють і оператор (пальцем), і PHANTOM (інструментами). Не «ще кнопки», а система здатностей, що знає, підказує, веде, попереджає і адаптується.

Прямі запити оператора (⭐):
- Моніторинг тривог: що за загроза, оновлення, інфо про місто.
- Тривога-«крик», якщо ціль рухається в бік району оператора.
- Адаптація PHANTOM, якщо оператор подорожує / опиняється в іншій країні.
- Маршрутні вузли транспорту, рекомендації при складанні/перегляді, **живі позиції транспорту**.
- Головне: **PHANTOM сам вміє цим керувати / демонструвати / підказувати / допомагати**.

## 1. ДЕВʼЯТЬ ЗАКОНІВ ЖИВОЇ МАПИ

1. **Мапа — орган, не вкладка.** Усе, що бачить оператор, PHANTOM теж «бачить» (`MapViewportSnapshot`) і може змінювати.
2. **Подвійне керування.** Кожна здатність має два входи: жест оператора **і** інструмент PHANTOM. Ніколи лише один.
3. **Чесність (Law 1).** Немає даних — немає рядка. Жодних фейкових пінів/маршрутів/тривог. Порожньо = чесно порожньо.
4. **Keyless-first.** Спершу безкоштовне без ключів. Ключі — опційне покращення, не вимога.
5. **Offline-виживання.** Критичне (укриття, збережені місця, останній стан тривог, кеш-регіони) працює без мережі. WorkManager для того, що мусить пережити kill процесу.
6. **Проактивність за згодою.** PHANTOM пропонує/попереджає тихо; «крик» — лише для життєвих загроз і за налаштуванням.
7. **Адаптивність до місця.** Мапа знає, оператор вдома, в дорозі, в іншому місті чи країні — і перемикає режим/джерела/тон.
8. **Одна лінза правди.** Один стек шарів (`SpatialLayerStore`), одна камера, один орб. Нові фічі — шари й дії, не окремі екрани.
9. **Розкриття за глибиною.** Порожній перший екран → тап → сенс → дія. Нічого не тисне, поки не питаєш.

## 5. АРХІТЕКТУРА РЕАЛІЗАЦІЇ

1. **Один стек шарів** — усе нове = `SpatialLayer` у `SpatialLayerRepository`. Нові типи шарів, не екрани.
2. **Дії = verb-и** — кожна взаємодія має tool-verb (`MapLayerTools`), який кличе і оператор (жест→viewModel), і PHANTOM (LLM→registry). Один код-шлях (reuse патерн `handleDirectHand` з чату).
3. **Клієнти даних — у `core-net`** — по одному тонкому suspend-клієнту на джерело, кеш + чесний fallback.
4. **Фонові watcher-и — WorkManager** (тривога-траєкторія, геозони) — переживають battery-kill.
5. **Контекст — розширити `MapViewportSnapshot`** до повного просторового стану.
6. **Схеми інструментів — через Gemini-адаптер** щоб cloud не 400-ив.
7. **Тести** — unit на клієнти/евристики (траєкторія, isochrone), E2E-чеклист по домену.
8. **Чесність вбудована** — кожен шар має «немає даних» стан; жодних плейсхолдерів.
